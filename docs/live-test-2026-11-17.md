# Live test log — 2026-11-17 (Z20, first real boots)

## Bootloader behaviour (verified on the device)

| Fact | Detail |
|---|---|
| `fastboot boot` | **not supported** — `FAILED (remote: 'unknown command')` after "Sending OKAY" |
| `fastboot flash` | works, but only after an unlock in the **same** bootloader session |
| unlock | `fastboot oem nubia_unlock NUBIA_NX627J` → `set state to 1 ok`; **does not persist** and `getvar unlocked` still says `no` |
| boot partition | `/dev/block/bootdevice/by-name/boot` → `sde11`, size `0x6000000` (96 MiB) |
| vbmeta / dtbo | `sde16` / `sde17` (`vbmetabak` `sde38`, `dtbobak` `sde39`) |
| ABL DTB selection | cmdline carries `androidboot.dtb_idx=11` and `androidboot.dtbo_idx=0` — the ABL picks entry 11 of the DTB table and then applies the dtbo overlay |
| verified boot | `ro.boot.verifiedbootstate=green`, `vbmeta.device_state=locked`, but **vbmeta flags = 0x2 (VERIFICATION_DISABLED)** → AVB is not what blocks a custom boot |
| TWRP USB | enumerates as `05C6:9039`; `adb` is root but drops after idle unless the screen timeout is raised |

## Boot attempts

| Image | Contents | Result |
|---|---|---|
| `boot-nx627j.img` (v0) | gzip(shim + Aloha FV) + payload, **single live FDT** appended | Nubia boot logo, then **dnmsRecovery** screen (green USB/wrench + QR) |
| `boot-nx627j-table.img` (v0) | same kernel, but the **stock 15-entry DTB table**, entry 11 patched with `/chosen` initrd | stuck on the **first boot screen**, no USB enumeration |

The second image differs only in the DTB payload, so the crash happens before UEFI reaches USB/display init. Candidates, in order:

1. the ABL expects a **v2 header** (stock is v2; our images are v0 with an appended `Image.gz-dtb`);
2. the shim assumes raphael's ramdisk/DTB pointer convention (`abl_base 0x80000000`, ramdisk at `0x80800000`, DTB pointer store at `0x9FF92000`);
3. the FDT the shim receives is not the one it expects (table vs single blob).

## Logs

* `/sys/fs/pstore` — empty; `/proc/last_kmsg` — absent (the chain runs XNU, not Linux);
* `logdump` (64 MiB) and `logfs` (8 MiB) — **entirely zero**, no ABL/UEFI log persisted;
